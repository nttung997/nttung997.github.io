Pick a mobile stack like a data engineer

23 Oct 2026 · React Native, Flutter, native
  • Most business apps: React Native + Expo if you have a JS/TS team; Flutter for pixel-identical custom UI; native when OS APIs or perf are the product.
  • Stack Overflow popularity for both frameworks peaked in 2021, then cooled — Flutter still leads React Native on level in 2023–2024.
  • The interesting signal is the derivative: growth flipped negative after 2021; 2024 looks like a flatline, not a collapse.
  • Vietnam banking: React Native + Expo Dev Client for retail UI; Soft OTP + PAD L2 + CCCD eKYC for NHNN; keep domain logic UI-free so AI/CLI can test it.

1. Decision matrix first

Before charts, the product constraint usually picks the stack. Roughly: one TypeScript codebase and a React shop → React Native + Expo. Brand-heavy identical UI or embedded/kiosk → Flutter. AR, on-device ML, attestation, or Metal/Vulkan-class work → Swift and Kotlin.

If you… Choose
Share code with a React/Next web app React Native + Expo
Need the same custom UI on every screen size Flutter
Ship AR, heavy ML, or regulated device checks Native (Swift / Kotlin)
Build a typical SaaS companion (forms, lists, payments) Either cross-platform stack

2. Get the data points

Metric: Stack Overflow Developer Survey “popularity” — share of respondents who said they used the framework that year. Six annual points, 2019–2024.

Year Flutter React Native
2019 3.40% 10.50%
2020 7.20% 11.50%
2021 13.55% 14.51%
2022 12.64% 12.57%
2023 9.12% 8.43%
2024 9.40% 8.40%

React Native led early. Both peaked in 2021. Flutter crossed above React Native on this series in 2023 and held a thin lead in 2024.

3. Draw the level chart

Level is \(f(t)\): how widely each stack was used, not how fast it was changing.

4. Compute the derivative

Annual finite difference: \(f'(t) \approx f(t) - f(t-1)\) in percentage points per year. Positive means adoption share rose; negative means it shrank.

Year Flutter Δ RN Δ
2020 +3.80 +1.00
2021 +6.35 +3.01
2022 −0.91 −1.94
2023 −3.52 −4.14
2024 +0.28 −0.03

Read it like a time series, not a beauty contest:

  • Max slope in 2021 — Flutter +6.35 pp/yr, React Native +3.01. That is the breakout year for both.
  • Inflection 2021→2022 — slope flips from positive to negative. Level is still high; velocity is not.
  • Steepest cool-down in 2023 — React Native −4.14, Flutter −3.52. Survey share compresses after the peak.
  • 2024 near flat — Flutter slightly up (+0.28), React Native basically zero (−0.03). Stabilization, not a wipeout.

Caveat: survey % is not installs, App Store revenue, or job demand. Native Swift/Kotlin live in different buckets, so this chart only compares the two dominant cross-platform options.

5. Banking (Vietnam): React Native stack

For a Vietnam-only retail bank, React Native + Expo Dev Client (EAS) is a solid UI shell — forms, lists, VietQR, onboarding. Expo Go is not enough: Soft OTP, CCCD NFC, certificate pinning, and RASP need custom native builds. The binding constraints are NHNN Circular 50/2024 and Circular 77/2025 (from Mar 2026): Soft OTP rules, biometric presentation-attack detection at ISO 30107 Level 2, OWASP MAS for mobile, and blocking rooted / jailbroken / emulator / injected devices.

Recommended layers

Layer Choice VN note
App shell RN + Expo Dev Client + TypeScript EAS builds; OTA only for non-security JS
Domain / use cases Pure TS package (no React Native imports) Same code path for app, Jest, and CLI / AI agents
Secure storage expo-secure-store behind a port Tokens / Soft OTP seed — never AsyncStorage
Network TLS + SPKI certificate pinning Primary + backup pins; rotation runbook
App unlock expo-local-authentication (strong) Local “device owner” check only — not bank authZ
eKYC / camera / NFC VN vendor SDK (VNPT, FPT, Kalapa, FinOS) CCCD OCR + chip + selfie → C06 / VNeID
Soft OTP Bank / HSM Soft OTP SDK Single-device activation, lockout, ~2 min TTL
Device integrity RASP (root / jailbreak / emulator) Fail closed or degrade high-risk features
Payments UI VietQR / NAPAS via bank APIs No global PSP required for VN-only

Auth matrix (NHNN-shaped)

Action Factors
Login / unlock app App PIN (≥6) or biometrics + server session
Low-risk (view, Type A/B) Session + basic OTP if bank policy requires
High-risk money move (Type C/D) Biometric match (PAD L2) + Soft OTP / Token / FIDO
New device / Soft OTP activate Full eKYC or ID step-up; bind to one device

UI vs logic (AI / CLI testable)

Split the app so screens are thin and business rules live in a pure TypeScript core. Adapters (camera, SecureStore, Soft OTP SDK, HTTP) sit at the edge. That lets you run the same use cases from Jest, a small Node CLI, or an AI agent without launching the simulator.

Layer Owns How you test it
packages/domain Limits, transfer rules, auth state machine, risk gates Unit tests + node cli.ts transfer … / AI-driven scripts
packages/adapters API client, SecureStore, Soft OTP, eKYC SDK wrappers Contract tests with mocks / recorded fixtures
apps/mobile Screens, navigation, permissions UI Detox / Maestro; keep scenarios thin

Pattern: hexagonal / clean architecture — domain depends on ports (SecureStorePort, OtpPort, BankApiPort); mobile and CLI each provide implementations. AI agents then exercise flows like “open session → quote transfer → confirm Soft OTP” against a sandbox BFF without touching React Native. Keep crypto, PIN hashing, and Soft OTP seed handling in native adapters — never reimplement them in the CLI for production secrets.

Soft OTP vs hardware token

In Vietnam, Soft OTP (in-app authenticator) is the retail default under NHNN rules. Hardware FIDO / token remains useful for corporate treasury and admin roles, but most consumer step-up is Soft OTP plus certified biometrics — not SMS alone.

Soft OTP (in-app) Hardware token / FIDO
Examples Bank Soft OTP SDK, push approve Bank token, FIDO2 USB–NFC
NHNN fit Primary retail path; seed in Keychain/Keystore Corporate / high-value / dual control
Risk Phishable if used alone; bind to device + PAD biometrics Logistics cost; phishing-resistant when FIDO2
SMS OTP Recovery / low-risk only — SIM swap and phishing make it a weak sole second factor

Practical cut: monorepo with domain + adapters + mobile; Expo Dev Client + SecureStore + pinning + RASP; one VN eKYC vendor (CCCD NFC + PAD L2); Soft OTP for transfers; VietQR via the bank backend. Limits and authorization stay on the server; the CLI only drives the same use-case API against a sandbox.

6. What to ship

Use the matrix for the build decision; use the series for confidence about ecosystem health. Both stacks are mature and still widely used. The derivative says the hypergrowth window closed after 2021 — pick for team fit and product constraints, not for chasing the steeper curve from three years ago. For Vietnam banking, treat UI stack, NHNN auth, and domain logic as separate decisions: React Native for screens; Soft OTP + PAD L2 + CCCD eKYC for regulation; a UI-free TypeScript core so humans and AI can regression-test flows from the CLI.
